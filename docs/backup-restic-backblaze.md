# Backup: originals-only to Backblaze B2 via restic

Goal: back up **originals only**. Thumbnails and transcoded/encoded video are regenerated by
Immich's jobs UI and cost real money to store in B2 at photo-library scale — skip them.

## Why a separate backup host

Run restic from a host that mounts `UPLOAD_DIR` **read-only**, not from the Immich host itself.
A compromised or buggy Immich process can't touch the backup credentials or the repo, and a
read-only mount means the backup job structurally cannot corrupt the source tree.

- Same idmap as the Immich container (immich uid 1000) so read permissions line up.
- If you don't want a second container, a read-only bind-mount plus a dedicated backup user
  on the same host gives the same property, just weaker isolation.

## Install restic

```bash
apt-get update && apt-get install -y restic
restic version
```

## Backblaze B2: bucket and application key

1. Create a B2 bucket (private).
2. Create an **Application Key** scoped to that bucket only (Backblaze console → App Keys).
   Don't reuse a master key — a scoped key limits blast radius if the backup host is compromised.
3. Note the **S3-compatible endpoint** for the bucket's region, e.g.
   `s3.us-west-001.backblazeb2.com`. B2's native API also works with restic, but the S3 endpoint
   needs no restic-side B2 support and is what's documented here.

## Secrets

Keep these out of git, mode 600/640, root-owned:

`/etc/restic/immich-password` — the restic repository password (not the B2 key). Generate once,
store safely outside the backup host too (losing it makes the whole repo unrecoverable):

```bash
openssl rand -base64 32 > /etc/restic/immich-password
chmod 600 /etc/restic/immich-password
```

`/etc/restic/immich.env`:

```bash
RESTIC_REPOSITORY=s3:https://s3.us-west-001.backblazeb2.com/<your-bucket>
RESTIC_PASSWORD_FILE=/etc/restic/immich-password
AWS_ACCESS_KEY_ID=<B2 application key ID>
AWS_SECRET_ACCESS_KEY=<B2 application key>
```

```bash
chmod 640 /etc/restic/immich.env
```

## Init the repo (once)

```bash
set -a; . /etc/restic/immich.env; set +a
restic init
```

## What to back up — and what to skip

`UPLOAD_DIR` (see [Storage and filesystem layout](storage-and-layout.md)) has originals mixed
with regenerable derived data. Back up:

- `library/` — originals, the whole point
- `upload/` — in-flight/unmatched uploads, also originals
- `profile/` — user avatars, small, cheap, easy to include
- `backups/` — Immich's own periodic DB dumps (gives you DB + media recoverability from one
  repo, no separate DB backup pipeline needed)

Skip:

- `thumbs/` — regenerated by **Administration → Jobs → Thumbnail Generation**
- `encoded-video/` — regenerated by Immich's transcoding job on demand

This is the majority of the storage-cost savings: thumbnails and transcodes can be a large
fraction of total tree size on a big library, and none of it is irreplaceable.

## Backup script

`/usr/local/bin/restic-immich-backup.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

set -a
. /etc/restic/immich.env
set +a

SRC=/mnt/photos

restic backup \
  "$SRC/library" \
  "$SRC/upload" \
  "$SRC/backups" \
  "$SRC/profile" \
  --tag immich \
  --exclude "$SRC/thumbs" \
  --exclude "$SRC/encoded-video"

restic forget \
  --tag immich \
  --keep-daily 7 \
  --keep-weekly 4 \
  --keep-monthly 6 \
  --keep-yearly 2 \
  --prune
```

```bash
chmod 750 /usr/local/bin/restic-immich-backup.sh
```

Replace `/mnt/photos` with your actual `UPLOAD_DIR`. Retention above (7 daily / 4 weekly /
6 monthly / 2 yearly) is a starting point — tune to your risk tolerance and B2 storage cost.
`--prune` reclaims space immediately instead of leaving it for a separate prune run.

## Schedule: systemd timer

`/etc/systemd/system/restic-immich.service`:

```ini
[Unit]
Description=restic backup of Immich originals to Backblaze B2

[Service]
Type=oneshot
ExecStart=/usr/local/bin/restic-immich-backup.sh
```

`/etc/systemd/system/restic-immich.timer`:

```ini
[Unit]
Description=Nightly restic backup of Immich originals

[Timer]
OnCalendar=*-*-* 02:09:00
Persistent=true
RandomizedDelaySec=600

[Install]
WantedBy=timers.target
```

`Persistent=true` catches up a missed run (host was off at the scheduled time). The jitter
avoids hitting B2 at exactly the same second as every other cron job on the internet.

```bash
systemctl daemon-reload
systemctl enable --now restic-immich.timer
```

## Operate

Manual run:

```bash
systemctl start restic-immich.service
```

List snapshots / check status:

```bash
bash -c 'set -a; . /etc/restic/immich.env; set +a; restic snapshots'
```

Restore (to a scratch path, then move into place — never restore directly over a live
`UPLOAD_DIR`):

```bash
set -a; . /etc/restic/immich.env; set +a
restic restore latest --target /mnt/restore-scratch
```

Periodically verify repo integrity (reads data back from B2, so it isn't free — run it
monthly, not nightly):

```bash
restic check
```

## What this doesn't cover

This backs up the **media tree**. It does not replace a direct Postgres backup — `backups/`
only has what Immich's own scheduled DB dump job produced. Confirm that job is enabled
(**Administration → Settings → Backup**) so `backups/` actually has something recent in it
before you rely on this as your only recovery path.
